# Milestone 5 implementation plan

[Issue #6](https://github.com/itguy614/roost/issues/6) tracks the desktop milestone. Start from `master` at the Milestone 4 merge, `adc27de`. Render the [approved UI v3](ui/README.md) against real daemon responses. Use light-first neutral surfaces, system typography, compact tables, semantic status labels, and equivalent dark-mode hierarchy. Keep the project table primary on a healthy dashboard and surface actionable failures first. Project detail has one primary Start or Stop action. A supported Restart Daemon action belongs under Advanced and requires confirmation.

## Architecture

- Put Tauri 2, Vue 3, TypeScript, Pinia, and Tailwind in `apps/desktop`. Use a desktop-specific Cargo manifest and lockfile so standalone daemon and CLI builds retain their current toolchain and dependency boundary. The Tauri Rust layer reuses `roost-ipc` for the private Unix socket. Vue gets explicit typed operations through Tauri commands and window-scoped capabilities. Grant access only to the installed local UI. Keep native directory selection narrow and render process output as text. [Tauri capabilities](https://v2.tauri.app/security/capabilities/)
- The daemon owns SQLite, configuration, process identity, and all mutations. Pinia keeps read snapshots, in-flight operations, scoped cursors and ephemeral view preferences. Separate desired from observed state and intent acknowledgement from completion. Share the same mutation paths between the main window, tray and CLI. For an uncertain response, retry the identical action with its original idempotency key. For a revision conflict, reload current data and show the conflict without silently replaying the edit.
- Negotiate IPC v1 and discover capabilities on every connection. Distinguish disconnected, incompatible, loading, stale and unsupported. Reconcile a reconnect from a fresh scoped snapshot and opaque cursors. Bound requests and subscriptions, coalesce refreshes, stop expensive refreshes on hidden views, and keep a single shared light health feed for the window and tray. Cancel or discard late results when their scope, connection or view changes.
- Use [current IPC](ipc-v1.md) for registration, worker and scheduler lifecycle, group operations, discovery, watchers, metrics and crash inspection. Verify any further command in daemon and CLI source before adding a control. Project/provider edits, worker-profile edit and scale, portable config, and daemon restart lack the public commands implied by the spec. Add the smallest reviewed v1 methods and CLI equivalents needed for parity. Do not bypass the daemon with direct file/DB writes or use a stop/restart workaround for scaling. Keep daemon restart and daemon login settings unavailable until a verified service lifecycle exists.

## Contracts to review before implementation

**Push data.** Follow the [Milestone 4 subscription contract](milestone-4-contracts.md#4-ipc-and-reconnect). Subscribe only on dedicated v1 connections after capability negotiation. Define bounded acknowledgement, payload and unsubscribe frames, handoff, backpressure and recovery. Keep existing request-response clients on identical shapes. Preserve separate event, raw-history and rollup cursors. On pruning, report the missed range and recover at the retained boundary. On lineage change, discard cached cursors and rehydrate. If push is unavailable, use one single-flight bounded poll per stream with backoff.

**Configuration and lifecycle.** Identify which fields are file-owned, editable locally or read-only before exposing each form. File-owned changes and resolution errors stay visible. Keep login preferences independent of project saved intent. The GUI and tray can exercise existing project autostart. GUI-login and daemon-login controls must reflect capability and actual service state. LaunchAgent installation, upgrades, daemon login lifecycle and distribution packaging remain Milestone 6.

**Notification navigation.** Separate receipt, OS acceptance and presentation. Richer notification text should use only approved project/profile display metadata, with a generic fallback. Exclude paths, queue credentials, process arguments, and logs. Define a bounded, opaque identifier route that opens or focuses the GUI and looks up the event and target through the daemon. Validate scheme and shape and resolve lineage and target before displaying detail. Treat deep links as untrusted navigation input. A missing, expired or offline target opens the relevant view with an explanation. Preserve the standalone helper as presenter, including when the window and GUI are both closed. Verify cold/warm activation against a locally signed app bundle and maintain a separate development identity. [Tauri deep linking](https://v2.tauri.app/plugin/deep-linking/)
